# 淡々施策系 第2弾（x-tantan-postスキルで生成）

### 1
```
個人開発のサブスクアプリは、無料プランを作るより最初から課金画面を出す方が効く。トライアルから有料への転換率は、ハードペイウォールで10%前後、フリーミアムで2%前後という目安がある。5倍の差を無料ユーザーのサーバー代で埋める体力は、個人開発にはない。
```

### 2
```
無料トライアルを3日に短くするのはやめた方がいい。有料への転換率は、4日未満で25%前後、17〜32日で40%前後という目安がある。短いと価値が伝わる前に切られる。まず2週間以上で出し、転換率が25%を超えるかを見る。削って浮くのは数日分のコストで、失うのは成約そのものだ。
```

### 3
```
年払いの契約は継続の証拠にならない。年払いの解約は3割以上が契約後1ヶ月目に集中するという目安がある。年払いで入った人には初月のうちに使い方のメールを3通送り、30日以内に主要機能を使ったかを確認する。1ヶ月目を越えれば、解約は更新月まで大きく減る。
```

### 4
```
解約率は、自分から辞めた人と決済失敗で落ちた人を分けて数えるべき。Google Playでは解約の3割前後が決済失敗によるという目安がある。カード期限切れの通知と再決済の導線を作るだけで、機能を1つも足さずに解約は減る。ここを放置して引き止め施策を考えるのは順番が逆だ。
```

### 5
```
広告の成果が落ちたら、予算より先にフリークエンシーを見る。新規向けで7日間のフリークエンシーが3を超えたら、同じ人に見せすぎている。色や文言だけの差し替えは同じ広告として扱われやすいので、訴求ごと作り直す。見せすぎた広告に予算を足しても、CPAが上がるだけになる。
```

### 6
```
iOSアプリは、説明文を磨くよりアプリ名とサブタイトルの60文字を磨く方が効く。検索で効くのはアプリ名、サブタイトル、キーワード欄で、説明文は順位に使われない。上位10アプリの名前とサブタイトルを並べ、拾えていない単語を探す。説明文は見つかった後に読まれる文章だ。
```

### 7
```
個人開発の手売りは、コミュニティで10回答えてからが絶対にいい。ターゲットが集まる掲示板で10件答え、名前を覚えられてから1回だけ紹介する。いきなりの宣伝は無視されるが、答えてきた人の紹介は相談として読まれる。広告費ゼロで最初の顧客を取るなら、この順番しかない。
```

### 8
```
AIで作り始める前に、仕様をA4一枚に書くべき。書くのは、誰が使うか、画面は3つまで、やらないことの3つだけ。一枚に収まらないアイデアは、MVPとしてまだ大きすぎる。仕様なしで投げると、AIが勝手に作った余計な機能を消すためにトークンを使うことになる。
```

### 9
```
機能を足す前に、使われていない機能を消すのが先。リリースから1ヶ月たって利用率が5%未満の機能は、画面から外す。機能が少ないほど初回の迷いが減り、問い合わせも保守も減る。使われない機能を残したまま次を作ると、守るコードだけが増えていく。
```

### 10
```
リリース告知を1回で終わらせるのはやめた方がいい。初回の告知を見ているのはフォロワーの一部だけだ。機能を追加するたびに「何ができるようになったか」を1投稿にして、月2回はリリースの話題を作る。アップデートは開発の報告ではなく、もう一度見つけてもらう機会になる。
```
