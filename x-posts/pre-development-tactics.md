# 淡々施策系 第3弾：アプリ開発前（x-tantan-postスキルで生成）

### 1
```
AIを使うアプリは、作る前に1ユーザーあたりの月の原価を出すべき。1回の処理のトークン数×1日の利用回数×30日で計算し、月額の2割以内に収まるかを見る。超えるなら、モデルを軽くするか回数に上限を付ける。原価を知らずに定額で売ると、使われるほど赤字が膨らむ。
```

### 2
```
アプリの審査は、出してから考えるのはやめた方がいい。App Storeは機能が薄いアプリや、既存とほぼ同じアプリをリジェクトする。作る前にガイドラインの4.2と4.3を読み、既存アプリとの違いを1行で書けるかを確かめる。書けないまま作ると、完成してから出す場所がなくなる。
```

### 3
```
価格を決めるときに「いくらなら買いますか？」と聞くのはやめた方がいい。聞くのは「安すぎて不安」「お得」「高い」「高すぎて買わない」と感じる値段の4つ。30人に聞き、「お得」と「高い」の間で、「高い」寄りに置く。1問で聞くと、相手は払いたい最安値しか答えない。
```

### 4
```
作るものを探すなら、ココナラやクラウドワークスで同じ作業が外注されているかを先に見る。毎月10件以上依頼が出ていれば、すでに財布は開いている。外注に5000円払う作業を月1000円で自動化できれば、説明しなくても売れる。誰も払っていない作業は、アプリでも払われない。
```

### 5
```
作る前に、最初の100人をどこから連れてくるかを3つ書くべき。「X」「広告」のような大きな言葉ではなく、掲示板やコミュニティの名前まで書く。3つ書けないアイデアは、どれだけ良くても届かない。作ってから集客を考えると、完成した日から何も起きない日が始まる。
```

### 6
```
需要検証のCPAの合格ラインは、自分で逆算するべき。月額×平均継続月数で1人あたりの売上を出し、その3分の1を許容CPAにする。月額980円で4ヶ月続くなら売上は約3900円で、許容CPAは1300円前後になる。逆算しないまま広告を回すと、合否を感覚で決めることになる。
```

### 7
```
サブスクにするなら、課題は週1回以上起きるものを選ぶべき。年に数回しか困らない課題は、困った月に入って翌月に解約される。直近1ヶ月で何回困ったかを聞き、4回未満なら買い切りか単発課金で考える。頻度の低い課題に月額を付けると、集めた分だけ抜けていく。
```

### 8
```
作り始める前に、一番不確かな機能だけを1日で試すべき。AIの精度、外部APIの制限、端末の権限など、ここが無理なら全部が無駄になる部分を先に動かす。1日で動かなければ、その時点で仕様を変える。ログイン画面から順に作ると、一番の問題に気づくのは3週間後になる。
```

### 9
```
作る前に、そのジャンルに許認可や規制がないかを1時間だけ調べるべき。送金や立て替え、健康や医療の効果、個人情報の大量取得は、法律の確認が要るものが多い。見つかった規制をクリアできないなら、個人開発には向かない。リリース後に止められると、集めたユーザーごと失う。
```

### 10
```
同じ機能を作るなら、個人向けより事業者向けの方が単価が取れる。個人は月500円でも迷うが、事業者は作業が月5時間減るなら月5000円でも経費で払う。作る前に、そのアプリを仕事で使う人がいるかを探す。月500円を100人集めるより、月5000円を10人集める方がはるかに早い。
```
