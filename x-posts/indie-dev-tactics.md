# 個人開発×プロダクトマーケ X投稿案（淡々・改行なし）

- 形式：改行なし、だ・である調で具体的な施策を淡々と述べる
- X無料版の上限（加重280）以内であることを全本確認済み

### 1
```
需要検証のLPは価格を載せた状態で出すべき。無料なら登録する人はいくらでもいるが、月額980円と書いた瞬間に本当に困っている人だけが残る。事前登録が100件集まっても、価格を見せていなければ需要検証としてはほぼ意味がない。
```

### 2
```
需要検証の広告は訴求を最低3パターン作り、同じ金額で回すのがいい。機能訴求、悩み訴求、ベネフィット訴求で比べると、CPAが2〜3倍違うことも珍しくない。勝った訴求がそのままLPのファーストビューとアプリの初期画面の設計図になる。
```

### 3
```
個人開発の最初のユーザー10人は、広告ではなくDMで集めるのが早い。課題をつぶやいている人を検索して20人に声をかければ、数人は話を聞いてくれる。15分で「今どう解決しているか」と「いくら払っているか」を聞くだけで、作るべき機能はほぼ決まる。
```

### 4
```
競合がいない市場を探すのはやめた方がいい。競合がいないのは、需要がないだけのことの方が多い。有料の競合が3社以上いて、レビュー欄に不満が溜まっている市場を選ぶ。星2〜3のレビューを50件読めば、作るべき差分と刺さる広告文がそのまま手に入る。
```

### 5
```
MVPは機能を削るより、対象を削る方が効く。全業種向けの予約アプリではなく、美容室の個人オーナー向けに絞る。ターゲットが狭いほど広告のCPAは下がり、LPの文章は短くなり、開発範囲も小さくなる。広げるのは有料ユーザーが30人ついてからで十分。
```

### 6
```
価格は安く始めて上げるより、高く始めて下げる方がいい。値上げは既存ユーザーの離脱を生むが、値下げは喜ばれる。最初は想定の1.5〜2倍で出して、LPのCVRが極端に落ちるかを見る。落ちなければその価格が正解で、個人開発の利益はほぼここで決まる。
```

### 7
```
リリース後に最初に見るべき数字は、DAUでも登録数でもなく、登録7日後に何%が戻ってきているか。ここが低いうちに広告費を増やしても、離脱する人を高いお金で連れてくるだけになる。継続率が安定するまでは、集客ではなく初回体験の改善に時間を使う。
```

### 8
```
「いいアイデアだね」は需要の証拠にならない。本当の検証になるのは、お金・時間・連絡先のどれかを差し出してもらえたかどうか。事前予約で500円でも決済してもらえたら、それは100件の「欲しい」よりはるかに強いシグナルになる。
```

### 9
```
個人開発のマーケは開発と同時に始めるのが正解。作りながら進捗をXに毎日投稿して、リリース前にフォロワーと待機リストを貯めておく。リリース日に0から集客するのと、待機リスト300人に一斉告知するのとでは、初週の数字がまるで違う。
```

### 10
```
需要検証のLPはノーコードで1日以内に作るべき。デザインに凝る必要はなく、必要なのは見出し、悩み、解決策、価格、登録ボタンの5つだけ。ここに3日以上かけている時点で、それはもう検証ではなく開発になっている。
```
