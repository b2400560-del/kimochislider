## 淡々施策系（SaaSの解約率・スキルのテスト出力）（5本）

### 1
```
SaaSの解約対策で最初に見るべき数字は、解約率ではなく契約後14日以内に主要機能を1回でも使ったかどうか。解約はたいていその時点で決まっている。14日過ぎて未使用の顧客にだけ電話かメールを入れる。解約申請が来てから引き止めるより、はるかに少ない工数で済む。
```

### 2
```
解約画面でいきなり50%オフを出すのはやめた方がいい。割引で残った顧客は数ヶ月後にまた解約し、その間の売上も半分になる。先に出すべきは月額の1割程度で1〜3ヶ月データを残せる一時停止プラン。停止した人の3割が戻れば、割引より利益は残る。
```

### 3
```
解約理由のアンケートは1問の選択式にして、解約ボタンの手前に置くべき。設問を増やすほど回答は雑になる。「高い」「使いこなせない」「乗り換えた」の比率を毎月見て、2割を超えた理由から潰す。理由を取らずに機能を足すのは、開発工数の無駄遣いで勿体無い。
```

### 4
```
解約率を下げるなら、機能追加より年払いプランを用意する方が効く。月額2ヶ月分を割り引けば、選んだ顧客は12ヶ月解約できない。年払い比率が3割を超えると月次の解約率のブレはかなり小さくなる。開発ゼロで継続率と手元資金を同時に取れる施策を後回しにするのは勿体無い。
```

### 5
```
SaaSのオンボーディングに必要なのは、初回ログインから3ステップ以内で最初の成果が出ることだけ。動画もツアーもいらない。初日に成果まで届いた顧客が5割を切るなら、新機能の開発を止めて手順を削る。成果を見ないまま2回目の請求日を迎えた顧客は、そこで解約を考える。
```

```
平均的な企業が価格を1%下げると
営業利益は約11%減るとされる

値下げは一瞬
取り戻すのは何年もかかる

「安くすれば売れる」の前に
「なぜ高くても選ばれるか」を考える
```

### 12
```
価格はコストから決めるものじゃない

・原価＋利益＝自社都合
・競合の横並び＝思考停止
・顧客が得る価値＝本来の基準

「この製品で顧客はいくら得するか」
ここを言葉にできれば
値段の話は交渉じゃなく説明になる
```

### 13
```
値下げを求められたら
まず疑うべきは価格じゃなく価値の伝わり方

「高い」の本当の意味は
・価値が伝わっていない
・比べる相手を間違えている
・決裁者に説明できない

この3つは
値引きじゃなく伝え方で解決できる
```

### 14
```
料金プランを3つ並べる理由

人は極端を避けて真ん中を選びやすい

・松：比較の基準をつくる
・竹：本当に売りたいプラン
・梅：入口のハードルを下げる

プラン設計は
値段の一覧じゃなく
顧客の選び方の設計
```

### 15
```
サブスクで見るべき数字は
新規の数より「解約しない理由」

・使い始めてすぐ価値を感じるか
・使い続けるほど便利になるか
・やめると困るか

ここまで設計できて初めて
集客にお金をかける意味が出る
穴の空いたバケツに水は貯まらない
```

### 16
```
「ドリルを買う人が欲しいのはドリルではなく穴である」

マーケの有名な格言

さらに言えば
欲しいのは穴でもなく
「棚を付けてスッキリした部屋」かもしれない

機能 → 結果 → その先の気持ち
どこまで掘れるかで提案の質が変わる
```

### 17
```
クリステンセンのミルクシェイクの話

味を改良しても売上は伸びなかった
調べると朝に買う人が多く
目的は「退屈な通勤を片手で紛らわすこと」

競合は他社のシェイクではなく
バナナやベーグルだった

顧客は商品を買うのではなく
「片付けたい用事」に雇っている
```

### 18
```
顧客インタビューで聞くべきは
「欲しい機能」じゃなく「過去の行動」

✕ この機能あったら使いますか？
○ 前回この問題が起きた時どうしました？

人は未来の自分について
ほぼ正確に答えられない

事実を聞くと
本当の課題とお金の流れが見えてくる
```

### 19
```
失注分析は一番安い市場調査

負けた商談には
・誰と比べられたか
・何が決め手だったか
・どこで不安になったか
が全部詰まっている

勝った理由より
負けた理由の方が
ポジショニングの改善点を教えてくれる
```

### 20
```
BtoBの買い手が営業と会う時間は
購買プロセス全体の約17%（Gartner調査）

残りは
・自分でネットで調べる
・社内で相談する
・情報を比較する

つまり営業がいない場所で
勝負の大半が決まっている

だから営業資料より先に
「自分で調べた時に伝わるか」を整える
```

### 21
```
新機能リリースで一番もったいないのは
「作ったのに誰も知らない」状態

全部を大きく告知する必要はない

・大型：プレスや記者向け発表まで
・中型：既存顧客へメールとウェビナー
・小型：リリースノートだけ

重さを分けると
本当に大事な発表がちゃんと届く
```

### 22
```
ローンチの成否は発表日に決まらない

発表日より大事なのは
・営業が説明できる状態か
・サポートが答えられる状態か
・既存顧客に何が変わるか伝えたか

社内に伝わってない機能は
社外にも伝わらない
```

### 23
```
営業がPMMに一番欲しいものは
きれいな資料ではなく
「競合と比べられた時の返し方」

・相手の強みと弱み
・よくある反論と切り返し
・乗り換えの決め手

1枚にまとめるだけで
営業の勝率は変わる
```

### 24
```
GTM戦略を一言で言うと
「誰に、何を、どうやって届けて、どう稼ぐか」

・誰に：ターゲット
・何を：価値の言葉
・どうやって：チャネル
・どう稼ぐ：価格と売り方

どれか1つだけ尖っても売れない
4つがかみ合って初めて事業になる
```

### 25
```
PLGとセールス主導は対立じゃない

・PLG：まず使ってもらい価値を体感させる
・SLG：課題を聞いて導入まで伴走する

小さく始めて
使い方が広がったところで営業が入る

「どっちか」じゃなく
「どこで切り替えるか」を設計するのが今の勝ち筋
```
